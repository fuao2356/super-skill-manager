# 协作模式库（2026-08-05 监理例会实战验证）

用户验证过的高效人机协作模式。**跨技能通用**——不只 PPT，任何"AI 出初稿 + 人修补"类任务（文档/报告/方案/表格）都适用。

## 1. 初稿 + 标注 → 用户查漏补缺（核心工作流）

用户原话："你给我初稿 我再查漏补缺一下 修补的过程中不需要你动手"

- AI 出**半成品**（不是做完的成品）+ **改动手册**（改了哪些/哪些没改/为什么没改——缺数据要标）
- 用户拿半成品自己收尾（质量/安全/协调等 AI 没数据的页）
- **AI 不主动参与修补阶段**——修补是用户最后一道质量门
- 反模式：给完初稿又追着问"要不要我帮你改"——越界；默默用猜的数据填——应标"⚠️ 待确认"

## 2. 截屏沟通 + 文字回填（审稿时的协作方法）

用户有疑惑内容 → **截屏发 AI → AI 识别转成清晰文字 → 用户粘回/确认**

- 截屏比文字描述准（"第5页那个表" vs 描述半天）
- AI 识别后**给出可直接用的清晰文字**（不是含糊描述，不是 JSON/dict）
- **一轮一轮聚焦一个疑惑点**，不一次性铺开
- 适用于：PPT 审校、表格数据核对、格式细节确认

## 3. 任务分工表（AI 单干 vs 人决策）

| 任务类型 | 谁做 |
|---|---|
| 数据替换（表格数字/改图/改格式/改日期） | AI 单干，不打扰，完事报告 |
| 设计决策（哪段话/要不要某页/业务准确性/风险判断） | 人，AI 一次多问 |
| 出初稿时列"我看到的数据源 + 合并假设" | AI，让人审解读是否对 |
| 文字润色/粘贴/最终审 | 人，AI 不主动参与 |
| 质量门（验证产物正确性） | AI，自检跑过才交付 |

## 4. 讨论驱动吸收（技能进化）

复盘工作流 → 讨论（用户定侧重点）→ 按骨架归位。见 super-skill-manager 模式3「框架内讨论」。

## 5. 多窗口并行问答

独立问题一次全抛（Hermes 桌面版多窗口分别答），效率远高于一问一答。不要退回"一问一答"旧模式。

## 触发信号 → 模式

- "你给我初稿 我自己查漏" → 模式 A（出初稿+标注）
- "补缺状态 / 你直接发文字我粘贴" → 模式 B（直接给文本，不动手）
- 产物被占用（PermissionError） → 模式 B
- 用户确认/在对话中 → 模式 A
